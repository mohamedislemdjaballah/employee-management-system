Part 1 • Introduction

What Is PostgreSQL?

A free, open-source relational database system.

Simple Definition

PostgreSQL is a database system designed to store your application’s data safely in organized tables, columns, and rows — so your data stays saved even if the app server crashes or restarts. It also provides essential features out of the box:

  • Fast searching & filtering across millions of rows in milliseconds
  • Automated backups to keep your data recoverable
  • Multiple clients at the same time without conflict
  • Wide range of column types (numbers, text, dates, booleans, and more)

Inside PostgreSQL: Schemas & Files on Disk

How PostgreSQL organizes databases logically — and how it stores them as files on your hard drive.

Logical Structure (Inside SQL)

Server (Cluster) — localhost:5432
Database — e.g. demo_db, company_db
Schema — folders (public, hr)
Tables & Indexes — public.employees

Physical Files on Disk (PGDATA)

/var/lib/postgresql/data/
├── base/
│   └── 16384/        -- demo_db folder (by ID)
│       ├── 16390     -- employees table
│       ├── 16390.1   -- next 1 GB chunk
│       └── 16395     -- primary key index
├── pg_wal/           -- crash recovery logs
└── postgresql.conf   -- server settings

Each table is stored as a binary file (split into 1 GB chunks if it grows large), and each index gets its own file.

A Brief History of PostgreSQL

From Ingres in the 1970s to nearly 40 years of continuous improvement.

1970sIngres built at UC Berkeley
→
1986Post-Ingres (“Postgres”)
→
1996Added SQL → PostgreSQL
→
TodayPowering apps worldwide

1. 1970s — INGRES

Professor Michael Stonebraker built INGRES (INteractive Graphics REtrieval System) at UC Berkeley. Its goal: proving the Relational Model could work, at a time when hierarchical and network databases dominated the industry.

2. 1986 — Post-Ingres (“Postgres”)

He started a brand-new successor to Ingres, written in C for speed and portability, and named it Post-Ingres → Postgres.

3. 1996 — PostgreSQL

Added standard SQL support and became a free, open-source project renamed PostgreSQL.

4. Today — Battle-Tested

Nearly 40 years of improvements and yearly updates powering apps around the world.

Part 5

Data Safety — ACID

Four guarantees that keep your data safe and consistent.

Part 4 • Data Safety

Why Is PostgreSQL So Safe? “ACID”

ACID is 4 simple promises that keep your data from ever getting corrupted.

A — Atomicity

All or nothing. Either every step succeeds, or none of it happens.

C — Consistency

Rules always hold. Invalid data is never allowed in.

I — Isolation

No clashing edits. Two people editing at once don’t break each other.

D — Durability

Saved forever. Once saved, it survives even a power cut.

Part 4 • ACID (1 of 4)

A — Atomicity (“All or Nothing”)

Example: Sending $50 from Alice to Bob.

Step 1Take $50 from Alice
→
Step 2: Crash!Power cuts before Bob gets $50
→
Undo (Rollback)Alice keeps her $50!

In Plain English

Both steps are glued together as one action. If Step 2 fails, PostgreSQL automatically undoes Step 1 so money never disappears into thin air.

BEGIN;
  UPDATE accounts SET balance = balance - 50 WHERE name = 'Alice';
  UPDATE accounts SET balance = balance + 50 WHERE name = 'Bob';
COMMIT;   -- saves BOTH
-- Or ROLLBACK; to undo BOTH if a step fails!
Part 4 • ACID (2 of 4)

C — Consistency (“Rules Always Hold”)

Example: Rule says balance can never be negative.

Alice’s Balance$40
→
Try to withdraw $100Would make balance -$60
→
Blocked by PostgresBalance stays $40 (valid!)

Main Constraint Types

  • NOT NULL — Cannot be empty
  • UNIQUE — No duplicate values allowed
  • PRIMARY KEY — Unique ID (NOT NULL + UNIQUE)
  • CHECK — Custom rule (e.g. balance >= 0)
  • FOREIGN KEY — Must match a row in another table
CREATE TABLE employees (
  id      INT PRIMARY KEY,
  name    TEXT NOT NULL,
  email   TEXT UNIQUE,
  balance INT CHECK (balance >= 0),
  dept_id INT REFERENCES departments(id)
);

UPDATE employees SET balance = -60;
-- ERROR: violates check constraint!

Data Types Are Enforced Too: PostgreSQL respects column data types — trying to save 'hello' into an INT column is rejected immediately.

Part 4 • ACID (3 of 4)

I — Isolation (“No Clashing Edits”)

Example: Only 1 concert ticket is left, and Alice & Bob click “Buy” at the exact same time.

Alice & BobClick “Buy” at 12:00:00
→
Alice goes 1stGets Ticket #1 (0 left)
→
Bob goes 2ndSees “Sold Out”!

In Plain English

PostgreSQL keeps simultaneous users isolated in a clean line so the same ticket is never sold twice.

-- Alice & Bob run this at the exact same time:
BEGIN;
  UPDATE tickets SET qty = qty - 1
  WHERE id = 1 AND qty > 0;
COMMIT;
-- Postgres runs 1st, then 2nd sees qty = 0!
Part 4 • ACID (4 of 4)

D — Durability (“Saved Forever”)

Example: Your order is confirmed, and 1 second later the server loses power.

Postgres says “Saved!”Written safely to disk
→
Power Goes OutServer restarts
→
Data Is Still ThereNothing was lost!

In Plain English

When PostgreSQL tells you “Saved”, it means the data is permanently written to disk — not sitting in temporary memory.

BEGIN;
  INSERT INTO orders (id, item)
  VALUES (1, 'Laptop');
COMMIT; -- Written safely to disk!
-- Even if power cuts 1ms later, order #1 stays!
Part 6

Basic SQL Syntax

Organized into DDL (structure), DML (changing data), and DQL (reading data).

Part 6 • Basic SQL Syntax

The 3 Main Types of SQL Queries

SQL commands are grouped by what they work on: structure, data changes, or reading.

DDL

Data Definition Language

Creates or changes structure (databases, tables, columns).

CREATE, ALTER, DROP

DML

Data Manipulation Language

Adds, edits, or removes rows inside a table.

INSERT, UPDATE, DELETE

DQL

Data Query Language

Reads and filters data without changing it.

SELECT, WHERE

DDL • Data Definition Language

1. Creating & Dropping a Database

Before creating tables, you need a database to hold them.

-- Create a brand-new database
CREATE DATABASE company_db;

-- Delete a database permanently
DROP DATABASE company_db;

Careful: DROP DATABASE deletes the entire database and every table inside it — there is no undo!

DDL • Data Definition Language

2. Creating & Dropping a Table

SQL is the simple English-like language we use to talk to PostgreSQL.

-- Create a new table
CREATE TABLE employees (
    id   INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY, -- auto-increments (1, 2, 3...)
    name TEXT,
    role TEXT
);

-- Delete the table and all its rows permanently
DROP TABLE employees;
  • CREATE TABLE employees — makes a new table named employees.
  • GENERATED ALWAYS AS IDENTITY PRIMARY KEY — automatically counts up (1, 2, 3...) for every new row.
  • DROP TABLE employees — permanently deletes the table and all of its data.
DDL • Data Definition Language

3. Adding & Dropping a Column (ALTER TABLE)

Change an existing table’s structure without deleting the table.

-- Add a new column to an existing table
ALTER TABLE employees
ADD COLUMN email TEXT;

-- Remove a column from an existing table
ALTER TABLE employees
DROP COLUMN email;

Tip: Use ALTER TABLE when your table already exists and you need to add or remove a column.

DML • Data Manipulation Language

4. Adding Data (INSERT INTO)

Insert new rows into your table.

-- Add a new employee (id is generated automatically!)
INSERT INTO employees (name, role)
VALUES ('Alice', 'Developer');

-- Add multiple employees at once
INSERT INTO employees (name, role)
VALUES
    ('Bob', 'Designer'),
    ('Charlie', 'Manager');

Tip: In SQL, text values always use single quotes ('Alice').

DML • Data Manipulation Language

5. Updating & Deleting Data (UPDATE & DELETE)

Always remember WHERE so you only touch the row you want!

-- Change Alice's role
UPDATE employees
SET role = 'Manager'
WHERE id = 1;

-- Remove employee #1
DELETE FROM employees
WHERE id = 1;

Careful: If you forget WHERE id = 1 on UPDATE or DELETE, it changes or deletes every row in the table!

DQL • Data Query Language

6. Reading & Filtering Data (SELECT)

Read rows from a table without modifying anything.

-- Read ALL employees
SELECT * FROM employees;

-- Read only specific columns
SELECT name, role FROM employees;

-- Filter rows with WHERE
SELECT * FROM employees WHERE id = 1;

Tip: * means “all columns”, and WHERE lets you filter only the rows you care about.

DQL • Data Query Language

7. Full SELECT & Execution Order

You write SELECT first, but PostgreSQL runs the clauses in a specific order.

SELECT department, COUNT(*) AS total
FROM employees
WHERE salary > 50000
GROUP BY department
ORDER BY total DESC
LIMIT 3
OFFSET 2;

Order of Execution

  • 1. FROM — choose the table
  • 2. WHERE — filter individual rows
  • 3. GROUP BY — group matching rows
  • 4. SELECT — pick columns & counts
  • 5. ORDER BY — sort the results
  • 6. OFFSET — skip the first N rows
  • 7. LIMIT — take the next N rows
DQL • Data Query Language

8. How GROUP BY Works (Split & Collapse)

GROUP BY splits your table into temporary sub-tables, then collapses each one into a single row.

SELECT department, COUNT(*) AS total
FROM employees
GROUP BY department;

Part 6 • Bonus (Object-Relational)

9. PostgreSQL Supports Objects Too!

PostgreSQL is an Object-Relational database — you can define your own custom object types (just like a class).

1. Define the Address Type

CREATE TYPE address AS (
    city TEXT,
    zip  TEXT
);

Groups city and zip together into one reusable address object.

2. Use address in a Table

CREATE TABLE employees (
    id           INT PRIMARY KEY,
    name         TEXT,
    home_address address
);

INSERT INTO employees (id, name, home_address)
VALUES (1, 'Alice', ROW('Rabat', '10000'));

SELECT name, (home_address).city
FROM employees; -- Alice | Rabat

Transactions (TCL)

  • BEGIN, COMMIT, ROLLBACK — group changes safely
  • SAVEPOINT — undo part of a transaction

Security & Automation (DCL)

  • GRANT & REVOKE — manage user permissions
  • CREATE TRIGGER & Functions — run logic automatically
