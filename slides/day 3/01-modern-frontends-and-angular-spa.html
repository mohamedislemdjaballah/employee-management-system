Web Evolution

Traditional Websites vs. Single-Page Applications (SPAs)

Traditional Websites (JSP / PHP / Forms)

  • Every click sends a request for a brand-new HTML page.
  • Server rebuilds the entire layout (Header + Menu + Table).
  • Browser wipes the screen white and redraws everything.
  • Slower navigation; UI tightly coupled to backend.

Single-Page Applications (Angular)

  • Browser downloads index.html & app engine ONCE.
  • Clicking buttons only requests small JSON data.
  • Angular swaps only the changed area in browser RAM.
  • Zero white-page flickering; desktop-like speed!

Core Architecture

The 3 Tiers: Dining Room, Kitchen & Pantry

1. DINING ROOM (Port 4200)

Angular Frontend

Runs inside Chrome browser.
Draws buttons, tables & forms.
NEVER talks to PostgreSQL.

2. KITCHEN (Port 8080)

Spring Boot Backend

Runs on application server.
Enforces security & business rules.
NEVER produces HTML.

3. PANTRY (Port 5432)

PostgreSQL Database

Persistent relational storage.
Tables: departments, employees.
Accessible ONLY by Spring Boot.

KEY RULE: Angular communicates ONLY with Spring Boot using REST APIs (HTTP + JSON) — never directly with PostgreSQL.

UI Anatomy

Angular Components — Building with Visual Lego Blocks

How a Page is Assembled

  • Navbar Component: Top blue header (MF / SIT) & navigation links.
  • KPI Summary Cards: Live counters (Total, Active, On Leave, Payroll).
  • Filter Toolbar: Search input & Department dropdown.
  • Employee Table: Rows, status badges & action buttons.

Why Teams Use Components

  • Reusability: Build a Status Badge once, reuse it across 10 screens.
  • Isolation: Updating styles inside one block won't break unrelated pages.
  • Maintainability: Faster to identify which visual block has a display bug.

UI Behavior

Templates & Real-Time Data Binding

What is Data Binding?

  • Automatic synchronization between data in browser memory and what is painted on screen.
  • When underlying data changes, Angular automatically updates text, badges, and totals—no manual refresh needed.

1. Filter Binding

Typing Karim or selecting SIT triggers an instant list update.

2. Dynamic KPI Cards

Filtering from 6 to 3 agents immediately updates Effectif Affiché & Payroll.

3. Conditional Badges

ACTIVE renders Green; ON_LEAVE renders Yellow automatically.

Business Input

Web Forms & Why Browser Apps Stay Responsive

Inside the Employee Form

  • Required Markers (*): Matricule, Last Name, First Name, Email, Salary, Date.
  • Dynamic Dropdowns: Direction list is fetched live from PostgreSQL via Spring Boot.
  • Action Controls: Clear distinction between Annuler and Créer l'agent.

Why Browser Calls Are Asynchronous

  • Java (Backend): Multi-threaded. One thread can pause waiting for DB without blocking others.
  • JavaScript (Browser): Single UI thread responsible for mouse clicks, typing, and drawing pixels.
  • Result: Angular fetches dropdown data in the background so your screen never freezes!

4 Morning Takeaways

  • Angular (:4200) and Spring Boot (:8080) are decoupled—Angular never touches PostgreSQL.
  • SPAs swap Components in browser memory via Client-Side Routing.
  • KPIs and tables react dynamically via Data Binding.
  • Frontend validation guides users; Backend validation protects DB.
