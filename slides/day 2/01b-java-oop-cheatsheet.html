1 Class vs. Object (new)

A Class is the blueprint. An Object is a real item built from that blueprint using new.

// The Blueprint (Class)
public class Employee {
    public int id;
    public String name;
    public String role;
}

// Creating Real Items (Objects) inside main()
Employee emp1 = new Employee();
emp1.id = 1;
emp1.name = "Alice";
emp1.role = "Developer";

Employee emp2 = new Employee();
emp2.id = 2;
emp2.name = "Bob";
emp2.role = "Designer";

2 Constructors & this

A Constructor lets you fill in the fields in 1 line when calling new. It has the exact same name as the class and no return type.

public class Employee {
    public int id;
    public String name;
    public String role;

    // Empty constructor
    public Employee() {}

    // Full constructor
    public Employee(int id, String name, String role) {
        this.id = id;
        this.name = name;
        this.role = role;
    }
}

// Now 1 line creates and fills the object!
Employee emp1 = new Employee(1, "Alice", "Developer");
Tip: this.name means “this object's field”, while name on the right is the value passed into the constructor.

3 Methods (Actions)

Methods are functions inside a class. Use void if the method returns nothing, or a type (like String or int) if it sends a value back with return.

public class Employee {
    public String name;
    public double salary;

    // Returns nothing (void)
    public void sayHello() {
        System.out.println("Hi, I'm " + name);
    }

    // Takes an input and returns a result
    public double getYearlySalary() {
        return salary * 12;
    }
}

// Calling the methods:
emp1.sayHello();
double yearly = emp1.getYearlySalary();

4 Encapsulation (public vs. private)

Make sensitive fields private so outside code cannot set invalid values, and expose safe public methods (getters/setters).

public class BankAccount {
    private double balance = 0;

    public void deposit(double amount) {
        if (amount > 0) {
            balance = balance + amount;
        }
    }

    public double getBalance() {
        return balance;
    }
}

5 Inheritance (extends) & Polymorphism (@Override)

A child class inherits fields & methods from a parent class using extends, and can customize a method using @Override.

// Parent class
public class Animal {
    public String name;

    public void makeSound() {
        System.out.println("Some sound...");
    }
}

// Child classes
public class Dog extends Animal {
    @Override
    public void makeSound() {
        System.out.println(name + " says: Woof!");
    }
}

public class Cat extends Animal {
    @Override
    public void makeSound() {
        System.out.println(name + " says: Meow!");
    }
}

6 Abstraction (interface & implements)

An interface defines a rule/contract. Any class that implements it must write the code for those methods.

public interface Printable {
    void print();
}

public class Invoice implements Printable {
    public void print() {
        System.out.println("Printing invoice...");
    }
}

Practice Try It Yourself: Build a Car Class

  • Create a Car class with public String brand; and public int speed;
  • Add a constructor Car(String brand, int speed)
  • Add a method drive() that prints: "Toyota is driving at 80 km/h"
  • In main(), create 2 Car objects and call drive() on both!
Show Solution 
public class Car {
    public String brand;
    public int speed;

    public Car(String brand, int speed) {
        this.brand = brand;
        this.speed = speed;
    }

    public void drive() {
        System.out.println(brand + " is driving at " + speed + " km/h");
    }

    public static void main(String[] args) {
        Car car1 = new Car("Toyota", 80);
        Car car2 = new Car("BMW", 120);

        car1.drive();
        car2.drive();
    }
}
